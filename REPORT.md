# CypherPanel — Repository Report

Compiled by reading the repository on a clean `main` checkout: the README, `docs/`, every module's package files, both entry points, the proto wire contract, the store layer, the plane and agent packages, the web source, installers, scripts, CI workflows and the git history. Nothing was built, run or modified. Anything that could not be confirmed from the files themselves is marked **UNVERIFIED**. No counts or measurements are repeated here, including the ones the README publishes.

---

## 1. What it does

CypherPanel is a self-hosted platform-as-a-service: a Go control plane (`cypherd`) keeps desired state in PostgreSQL, and a Go agent per server (`cypher-agent`) dials home over mTLS to build, run, route, back up and update applications, managed databases and compose stacks on Docker hosts.

## 3. Architecture

### Components

**Control plane, `cypherd`** (`core/cmd/cypherd/main.go`). One process with separate listeners: HTTP for the REST API and the embedded SPA; gRPC over TLS for enrollment, renewal and the image relay (client certificate optional at the TLS layer, required by the relay handlers); and the embedded NATS JetStream server over mTLS with a client certificate required. Subcommands on the same binary: `version`, `migrate`, `restore` (rebuild a plane from an age-encrypted snapshot), `upgrade` (a root one-shot started by a systemd path unit when the plane writes a request file) and `join-local` (installs an agent on the plane's own host the same way).

Inside the plane:

- `core/api/rest/` — handlers, authorization (`authz.go`), trace-id and trusted-proxy middleware, SSE helpers, the OpenAPI document, the embedded web bundle (`webui/`) served with a strict CSP, and the embedded copy of the agent installer.
- `core/api/grpc/` — enrollment and relay servers.
- `core/<feature>/` service packages (applications, projects, teams, servers, databases, compose, protection, audit, inbox, notify, webhooks, sharedvars, templates, previews, registries, deploykeys, githubapp, dns, mail, mailhost, logdrain, planebackup, quota, agentupdates, upgrade, statuspage, alerts, usage, export, access, onboarding, paneltls, localjoin, updates, egress, guard, logring, secret, identity, enroll, status). Each declares the store interface it consumes; `core/store.Store` satisfies them.
- `core/scheduler/` — turns a Deployment into work items and advances it only from what agents report.
- `core/bus/` — the embedded NATS server: STATE (memory), WORK (file-backed, survives restarts), LOGS (memory) and RUNTIME_LOGS (file-backed) streams; a per-identity authorizer that refuses de-enrolled certificates and scopes each agent to `state.<id>.>`, `logs.<id>.>`, `work.<id>.>`, its own JetStream consumer API subjects and its own reply inbox prefix. The subject contract lives in `pkg/subjects/`.
- `core/store/` — the only PostgreSQL writer; domain types in `core/domain/`.

**Agent, `cypher-agent`** (`agent/cmd/cypher-agent/main.go`). Subcommands `enroll` and `run`; roles `all`, `builder`, `worker`. Packages: `conn` (gRPC enroll and the outbound NATS dial), `identity` (on-disk identity, a keeper that serves the current certificate to every TLS handshake, a renewer that re-keys part-way through certificate life), `heartbeat` (liveness, disk, subsystem health, update phase), `worker` (pull consumer, dispatch, ack/nak/term, poison cutoff), `driver` (the desired-state driver contract) and `driver/docker` (application reconciler, database reconciler, backup executor), `driver/docker/engine` (raw Engine API), `driver/docker/prober` (health probes), `driver/docker/metricsource`, `builder` (clone, build-kind detection, Dockerfile/static/Nixpacks/Railpack, an additional buildx transport for BuildKit-only output), `proxy` (Traefik container lifecycle, static config, per-app file-provider fragments, ACME settings, the maintenance responder), `compose` (a `docker compose up` reconciler with revision markers), `cron` (scheduled tasks exec'd inside the app container), `stream` (runtime log streaming), `metrics` (bucketed container and access-log metrics), `relay` (push/pull of image tars through the plane), `updater` (signed self-update with an alternating-slot swap and probation).

**Shared, `pkg/`**: generated proto stubs, subjects, `pki` (CA, CSR signing, TLS configs), `ids` (prefixed identifiers), `s3`, `fetch`, `registryauth`.

**Web UI, `web/src/`**: file-based routes under `routes/` (projects → applications, compose stacks, databases; servers; settings; templates; inbox; login; invitation accept), one fetch wrapper (`api/client.ts`) behind the generated client, SSE hook (`lib/use-sse.ts`), design tokens in `styles/globals.css`, hand-written primitives in `components/ui/`.

**Build-time tools, `core/cmd/`**: `coolify-import` (translates Coolify's compose templates into the native catalog schema and pins image digests), `docs-site` (static docs site from `docs/` plus the OpenAPI file), `release-sign` (offline Ed25519 signing and verification), `release-manifest` (writes `release.json`).

**Install and operations**: `install/install.sh` (plane), `install/agent.sh` (agent; also served by the plane), systemd service and path units, `deploy/docker-compose.yml` with `cypherd.env.example`, `scripts/` for release rehearsal, fresh-host rehearsal, release signing, e2e and the parity audits.

### Data flow

1. **Write path.** An operator, the SPA or CI calls the REST API with a bearer session or API token (the GitHub webhooks authenticate by HMAC instead). A handler calls a service, the service writes through `core/store` to PostgreSQL, and secret values are sealed with AES-GCM under `CYPHERD_MASTER_KEY` before they are stored. Sensitive handlers append an audit row in the same request.
2. **Deploy.** A deploy mints an immutable Revision and a Deployment row. The scheduler consults the deploy-protection gate and the quota gate, then publishes work messages (`BuildWork`, `PushImageWork`, `DistributeWork`, `RolloutWork`, `RemoveWork`, database, compose and backup work; all in `proto/cypherpanel/agent/v1/work.proto`) to `work.<server>.*` on the file-backed WORK stream.
3. **Agent side.** The agent, authenticated by its plane-issued client certificate, pulls from its own durable consumer. A build clones the repository (deploy key, or a per-build GitHub App token passed through an askpass helper), picks a build kind, and builds the image locally. A rollout starts the new container beside the old one, health-probes it, rewrites the Traefik fragment, then drains the old container. The agent also asks the plane for the full `DesiredState` over its private reply inbox and converges the whole host against it: absent applications are removed, a retain set bounds which images are kept, ACME settings and static routes are applied, agent-update channels are honoured.
4. **Observation.** Heartbeats go to `state.<server>.heartbeat`; deploy events, application, database, compose, backup, restore, task-run and metrics reports go to other `state.<server>.*` subjects; build and runtime logs go to `logs.<server>.*`. The plane consumes these: the status recorder updates servers and disk, the scheduler advances Deployments and fans terminal outcomes to notifiers, outbound webhooks and the inbox, and the usage recorder buckets metrics.
5. **Multi-server images.** When builder and target differ, the builder streams the image tar over gRPC into an in-memory rendezvous in the plane (`core/relay`) and the target pulls it out (`agent/relay`); nothing lands on plane disk.
6. **UI freshness.** The SPA holds an SSE connection (`core/api/rest/handlers_events.go`) that carries "this resource changed" events and refetches through the generated client; build and runtime logs stream over SSE with a replay window (`core/api/rest/sse.go`).
7. **Background goroutines in the plane** (all owned and cancelled from `main`): stale-heartbeat sweeper, preview TTL sweeper, backup cron evaluator, webhook retry sweeper, DNS reconciler, session purge, audit retention, release check, status-page evaluator, alert evaluator, plane snapshot scheduler, log-drain manager, usage rollup, upgrade-snapshot retention.

## 4. Features implemented

The features below are the ones whose implementing code was read end to end. The README and `CLAUDE.md` list many more; this is a sample, not the whole set.

1. **Agent enrollment, mTLS identity and self-renewal.** A single-use join token plus a CSR yields a client certificate signed by the plane's own CA; the private key never leaves the host; renewal re-keys over the authenticated channel and revocation refuses both the bus connection and renewal.
   `proto/cypherpanel/agent/v1/agent.proto`, `core/api/grpc/enrollment.go`, `core/enroll/enroll.go`, `core/identity/identity.go`, `pkg/pki/pki.go`, `agent/conn/conn.go`, `agent/identity/keeper.go`, `agent/identity/renew.go`.

2. **Embedded NATS JetStream bus with per-agent authorization.** In-process server, mTLS listener, per-identity subject grants including a private reply inbox so no agent can read another's desired state, file-backed durable work queue.
   `core/bus/bus.go`, `pkg/subjects/`, `agent/worker/natsbus.go`, `agent/worker/worker.go`.

3. **The deploy pipeline: build, health-gated rollout, routing, rollback.** Scheduler-driven work items; local image build with Dockerfile, static, Nixpacks and Railpack kinds; zero-downtime container swap; Traefik file-provider fragments with optional ACME; rollback re-points desired state without a rebuild; cancel and restart as desired state.
   `core/scheduler/scheduler.go`, `agent/builder/builder.go`, `agent/builder/detect.go`, `agent/builder/pack.go`, `agent/builder/buildkit.go`, `agent/driver/docker/docker.go`, `agent/driver/docker/engine/engine.go`, `agent/driver/docker/prober/prober.go`, `agent/proxy/traefik.go`, `agent/proxy/ensure.go`.

4. **Managed databases with S3 backups and restore.** Engine-specific container specs reconciled by the agent, sealed root credentials, plane-side backup cron, agent-side dump/restore over the Docker archive API with progress events, S3 object pruning.
   `core/databases/`, `core/scheduler/backups.go`, `agent/driver/docker/database.go`, `agent/driver/docker/backup.go`, `agent/driver/docker/s3.go`, `pkg/s3/s3.go`.

5. **Compose stacks as a first-class resource.** The compose file is the desired state; the agent runs one fixed `docker compose up` with an env file written and removed per run; revisions and rollback re-point the file; routing goes through the same Traefik fragment an application gets.
   `core/compose/`, `agent/compose/compose.go`, `core/api/rest/handlers_compose.go`, `core/templates/catalog/openclaw.yaml` (the compose-stack template).

6. **Deploy protection: approvals, freeze windows, break glass.** Gate evaluated once where a Deployment is born; parked deployments carry `awaiting_approval`; weekly zone-aware freeze windows; a recorded owner override; the decision routes are session-only so an API token cannot approve its own deploy.
   `core/protection/`, `core/api/rest/handlers_protection.go`, `core/store/deploy_protection.go`, `web/src/routes/_app/projects/$projectId/settings/protection.tsx`.

7. **Immutable audit log.** One row per sensitive action with actor, resource, client address and outcome; no foreign keys so an entry outlives what it names; scope-based read authorization; secret-shaped keys stripped on write; hourly bounded retention sweep.
   `core/audit/`, `core/store/audit.go`, `core/api/rest/handlers_audit.go`, `web/src/routes/_app/settings/audit.tsx`.

8. **Signed agent self-update.** Per-server channel selection carried in desired state; the agent fetches a manifest, signature and binary, verifies Ed25519 then digest against keys baked in at link time, pre-flights the staged binary, swaps between alternating slots with a marker, and rolls back if the new binary cannot dial home. CI publishes only a draft; a human signs offline.
   `agent/updater/updater.go`, `agent/updater/keys.go`, `agent/updater/swap.go`, `core/agentupdates/agentupdates.go`, `core/cmd/release-sign/main.go`, `scripts/release-sign.sh`, `release-pubkey.txt`, `.github/workflows/release.yml`.

Also read and confirmed present: the template catalog and its importer (`core/templates/`, `core/cmd/coolify-import/`), the GitHub App integration (`core/githubapp/`), team invitations and access requests (`core/access/`), log drains to Loki, syslog and S3 (`core/logdrain/sinks.go`), plane disaster recovery (`core/planebackup/`), the guided panel upgrade helper (`core/upgrade/`, `install/cypherd-upgrade.service`), the documentation-site generator (`core/cmd/docs-site/`), and the PR review bot (`.github/review-bot/policy.mjs` with tests).
